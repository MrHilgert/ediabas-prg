# Handoff: eDIAG — диагностический интерфейс BMW (egui)

## Overview
Настольное диагностическое ПО для автомобилей BMW E-серии в стиле «строгий инженерный
терминал». Три связанных экрана одного потока:

1. **Выбор кузова (Chassis Select)** — выбор шасси по серии (1/3/5/6/7/8/X/Z).
2. **Выбор ЭБУ (ECU Select)** — список блоков управления выбранного шасси со сканом статусов.
3. **Сессия ЭБУ (ECU Session)** — INPA-подобный экран работы с блоком, **шаблонный и
   полностью управляемый конфиг-данными**.

Поток: на экране 1 **двойной клик** по карточке кузова → экран 2. На экране 2 **двойной
клик** по строке модуля (или кнопка «Подключиться») → экран 3. Возврат — кнопками «‹» в шапке.

## About the Design Files
Файл `Chassis Select.dc.html` — **дизайн-референс в HTML**: рабочий прототип вида и
поведения, **не код для копирования**. Целевое окружение — **нативное приложение на
Rust + [egui](https://github.com/emilk/egui)**. Задача — **воссоздать эти экраны средствами
egui** (панели, `Grid`, `Frame`, `Visuals`), а данные и структуру взять из прототипа
один-в-один. Прототип интерактивен: откройте в браузере и «прокликайте» все три экрана.

## Fidelity
**High-fidelity.** Финальные цвета, типографика, отступы, состояния и микровзаимодействия.
Воссоздавать пиксель-в-пиксель средствами egui. «Мягких» плейсхолдеров не осталось.

- Скругления 3px (`Rounding::same(3.0)`); окно/панели по краям без скругления.

## Экран 1 — Выбор кузова (Chassis Select)
Раскладка: шапка (48) · `[SidePanel left 186] [CentralPanel]` · футер (26). **Правой панели
нет** (убрана намеренно). Левая панель — список серий со счётчиками (активная: фон
`accent-tint`, левый бордер 3px `accent`). Центр — тулбар (заголовок «ВЫБОР КУЗОВА / E-СЕРИЯ»,
поле поиска с префиксом «›», счётчик результатов, подсказка «2× — открыть») + сетка карточек
`minmax(154px,1fr)`, gap 10, padding 14.

**Карточка кузова** (кнопка, min-height 106, padding 10×11, скругл. 3px): код (21px, вес 700),
модель (11px `fg-dim`), годы (11px `fg-faint`), внизу через `border-top`: коды кузовов через «·»
(с ellipsis) и «N ECU». Выбранная: фон `accent-tint`, рамка 1px `accent`. **Двойной клик →
подключение к шасси и переход на экран 2**; одиночный клик — только подсветка.

Данные: 28 реальных шасси BMW (E21…E90, E12…E60, E24/E63, E23…E65, E31, E53/E70/E83/E71,
E36-7/E85/E52). Поля см. в `DATA` внутри прототипа: `code, series, name_ru/en, years, bodies[],
drive[], engines[], ecus, status`.

## Экран 2 — Выбор ЭБУ (ECU Select)
Раскладка: шапка (с «‹ КУЗОВ» и контекстом `E46 · 3 серия · седан`) · `[left 186] [center]
[right 346]` · футер. Слева — фильтр по системам (ВСЕ + PWR/CHS/SAF/BDY/GWY/INF) со счётчиками
+ легенда статусов (норма/ошибки/нет связи). Центр — тулбар (заголовок, счётчик, сводка
«N с ошибками», кнопка «СКАН ВСЕХ» с анимацией прогресса) + шапка столбцов + плотная таблица
модулей: колонки `14px 62px 1fr 58px 46px 78px` (точка-статус · КОД · СИСТЕМА · ШИНА · АДРЕС ·
СТАТУС). Строка выбранного модуля: `accent-tint` + левый бордер 2px. **Двойной клик → сессия.**
Справа — карточка модуля (код, имя, статус, категория/шина/адрес/номер детали/версия, коды
ошибок или «нет связи», кнопки «ПОДКЛЮЧИТЬСЯ» / «ЧИТАТЬ ОШИБКИ» / «СБРОС» / «ЖИВЫЕ ДАННЫЕ»).

Данные: список модулей строится **под конкретное шасси** — из каталога `MODS` по перекрытию
годов и признаку привода (`from`/`to`/`cond:'awd'`). Статусы (норма / N DTC / нет связи)
детерминированы от хэша кода модуля (см. `enrich()`), скан — анимация `scanState/scanPct`.

## Экран 3 — Сессия ЭБУ (ECU Session) — ШАБЛОННЫЙ, КОНФИГ-УПРАВЛЯЕМЫЙ
**Ключевая архитектура.** Экран один для всех блоков; всё содержимое приходит из
**конфиг-данных в коде** — дерева страниц. Раскладка: шапка (с «‹ ЭБУ» и контекстом
`E46 · DME · Двигатель`) · заголовок страницы + хлебные крошки стека + чип `CFG · dme.ecu` ·
тело (рендер блоков) · **INPA-панель F-клавиш** (~64px) · футер.

### Модель конфига (перенести как структуры Rust)
- **Дерево страниц** `screensFor(em) -> HashMap<PageId, Page>`. Каждая `Page`:
  `{ title:{ru,en}, blocks:[Block], keys:[FKey] }`.
- **Block** (тип-размеченный, обрабатывается generic-рендерером):
  - `note` — строка текста.
  - `menu` — список пунктов `{label, to}` → навигация в дочернюю страницу (вложенность).
  - `kv` — таблица идентификации (генерится из хэша: номер детали, HW/SW, индексы, шина/адрес,
    поставщик, дата, VIN).
  - `faults` — память ошибок: состояния `unread` (F1 читать) / `empty` (пусто) / `list`
    (код + описание + статус present/stored). Описания — из `FAULTDESC[category]`. **Строка ошибки
    раскрывается по клику** (caret ▸/▾, состояние `faultOpen`): подробное описание, блок «СВЕДЕНИЯ»
    (статус, счётчик появлений, пробег при фиксации, приоритет) и блок «СТОП-КАДР ПАРАМЕТРОВ»
    — снимок значений (обороты, ОЖ, скорость, нагрузка, напряжение, темп. впуска), захваченных
    в момент фиксации. Все значения детерминированы от хэша кода ошибки.
  - `stream` — живые параметры (см. ниже).
  - `status` — строки состояния (клемма 15, связь, кодирование, память).
- **FKey** — позиционная функц-клавиша: `{ f:1..6, label:{ru,en}, to? | back? | exit? |
  action:'read'|'clear' }`.
- **Стек навигации** `sesStack: Vec<PageId>` (push при заходе в подстраницу, pop — «Назад»;
  на `main` «Выход» → экран 2). Хлебные крошки = названия страниц стека.

### INPA-панель F-клавиш
Ряд из **6 позиционных клавиш** F1…F6 (недостающие — пустые серые слоты, как в INPA). Каждая:
тег `F#` (цвет по типу: навигация — `accent`, назад/выход — `fg-faint`, читать — `ok`, сброс —
`warn`) + подпись. Работают мышью и **с клавиатуры**: `F1–F6` и цифры `1–6`, `Esc` — назад.
Пример главного меню: F1 ИДЕНТ · F2 ОШИБКИ · F3 ПОТОК · F4 СТАТУС · F5 АКТИВ. · F6 ВЫХОД.

### Поток данных (stream) — важные детали
- Параметры заданы в **конфиге по категории блока** (`streamGroups(cat)`): для PWR — группы
  Двигатель/Топливоподача/Электрика; для CHS — Скорости колёс/Динамика; иначе — Основные.
  Каждый параметр: `{ name:{ru,en}, unit, base, amp, min, max, dec?, bool?, lo?, hi? }`.
- **Живые значения**: `v = base + amp·sin(tick·0.7 + i·1.3) + шум`, тик каждые 600 мс
  (в egui — `ctx.request_repaint_after` + фаза от времени/телеметрии).
- **Вёрстка**: 2 колонки (`grid 1fr 1fr`, ширина 100% — тянутся на весь экран, без пустот),
  строка = `имя(150) · трек-бар(1fr) · значение+ед.(96)`. Высота бара **15px**.
- **До 10 баров на экран**; ряды распределяются по высоте (`align-content:space-between` в
  колонке, грид тянется `flex:1`) — при 3 рядах большие зазоры, при 5 — плотно. Без нижней пустоты.
- **Пороговые зоны (min и max)**: у параметра могут быть `lo` и/или `hi` (доля 0..1 диапазона).
  На треке рисуются **вертикальные метки `err`** в этих позициях. Если значение **выше `hi`
  ИЛИ ниже `lo`** — заливка бара и число становятся **красными (`err`)**. Примеры в конфиге:
  ОЖ `hi:0.7` (демо-перегрев → красный), Обороты `hi:0.82`, Нагрузка `hi:0.85`,
  Напряжение АКБ `lo:0.75, hi:0.95` (обе метки), Лямбда `lo:0.35, hi:0.65` (обе метки),
  Давление топлива `lo:0.5`.

### egui-заметки по сессии
- Тело — вертикальный контейнер; страница потока данных заполняет высоту, ряды распределяются
  равномерно (в egui: `ui.available_height()`, разложить N рядов с равным зазором; либо
  `Grid` с ручным spacing = `(avail - rows·row_h) / (rows-1)`).
- Бар: `Rect` трека (`stroke` fill) + `Rect` заливки (accent/err по `pct`) + вертикальные
  линии-метки на `lo`/`hi` (2px `err`). Значение — крупное моно, красное при выходе за зону.
- Функц-панель: 6 равных кнопок `flex:1`; пустые — `opacity 0.3`, некликабельны.

## Interactions & Behavior (сводно)
- Экран 1: клик серии — фильтр + автоподсветка первого шасси; поиск фильтрует по всем сериям;
  **двойной клик карточки → экран 2**. RU/EN и тема — мгновенно.
- Экран 2: клик категории — фильтр; клик модуля — карточка справа; **двойной клик / «Подключиться»
  → экран 3**; «СКАН ВСЕХ» — анимация прогресса, статусы норма/N DTC/нет связи.
- Экран 3: меню/F-клавиши → навигация по стеку страниц; «Читать/Сброс» меняют состояние памяти
  ошибок; поток — живые значения с порогами; «Назад»/«Выход» — по стеку/на экран 2. Клавиатура
  F1–F6 / 1–6 / Esc.
- Глобально: пульс индикатора связи (opacity 1→0.3→1, 2 с), часы и VBAT в футере (тик 1 с).

## Files
- `Chassis Select.dc.html` — эталонный прототип (все 3 экрана, стили, данные и логика в одном
  файле). Источники истины: `DATA` (шасси), `MODS` (модули), `FAULTDESC` (описания ошибок),
  `screensFor()` / `streamGroups()` (дерево страниц и параметры потока), `STR`/`BODY`/`SNAME`
  (локализация). Копировать эти структуры в Rust напрямую.
