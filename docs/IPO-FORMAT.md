# INPA `.ipo` формат — заметки реверс-инжиниринга

Источник экранов диагностики eDIAG. Файлы лежат в `SGDAT/` (gitignored). Парсер —
`tools/ipo_parse.py`. Мы **не исполняем** байткод: майним упорядоченный поток строк
(надёжно, ~4.5/5) и классифицируем по содержимому. Точная пиксельная раскладка зашита в
опкодах (2.5/5) — сознательно **не** восстанавливается (выбрана семантическая точность).

## Инвентарь корпуса

- `SGDAT/` = **710** уникальных `.ipo` (Windows — регистронезависимая ФС; `glob('*.IPO')` и
  `'*.ipo'` матчат одно и то же — дедуплицировать по имени!).
- **468** начинаются с фингерпринта; из них **~440 экранных скриптов** (есть `m_main`) —
  это цель. Остальные — старые/библиотечные форматы (job/coding-библиотеки).
- Компаньоны `.ini` (121) — текстовый инвентарь экранов `[OBT_SCREEN]` (имена+порядок+
  `SelectSetCount`), без геометрии. Полезны для сверки дерева.

## Бинарный формат

Компилированный **стековый p-code** с inline-пулом строк. Нет магии/версии/оффсет-таблиц —
плоский поток записей: определения объектов, литералы и код вперемешку.

### Фингерпринт
Файл начинается с `05 00 "TEST-Infotext" 0a`. Проверка экранного скрипта:
префикс `05 00 TEST-Infotext` **и** наличие `m_main\n` (или `s_main\n`).

### Строки
Строка = **печатаемый ран, завершённый `0x0a`**. Кодировка — **Windows-1251** (кириллица
лейблов). Некоторые строки имеют ведущий тег (1 байт), многие операнды — **без тега** (голые,
подразумеваются опкодом). Поэтому сканируем **тег-независимо** (`strings`-стиль с терминатором
`0x0a`, CP1251) и классифицируем по содержимому.

Теги (когда присутствуют):
| Тег | Значение |
|-----|----------|
| `05` | идентификатор / имя процедуры |
| `06` | строковый литерал (константа) |
| `01` | имя экрана (`s_*`) |
| `02` | имя меню (`m_*`) |
| `0e 00 00 00` | define-object (перед именем узла/процедуры) |
| `0c 81 XX` | вызов builtin `XX` (0x80 = внешняя/рантайм-примитива) |
| `03 XX 00` | push 16-бит immediate (координаты/цвета/ключи) |

## Структура экранного скрипта (пример DDE40.IPO)

Файл делится на регионы:
1. **Процедуры** сверху: `ergebnisTextAusgabe`, `ergebnisDigitalAusgabe`,
   `ergebnisAnalogAusgabe`, `ergebnisUmrechnungAnalogAusgabe`, `ansteuerung`.
2. **Узлы меню/экранов** — имена по универсальной конвенции `m_*` (меню) / `s_*` (экран):
   `m_main/m_fehler/m_status/m_steuern/m_ews/m_abgleich`, `s_ident/s_info/s_code/s_digital/
   s_analog1..5` (+ вариант-суффиксы `_d40m57a1`). Конвенция `m_*`/`s_*` универсальна во всех
   поколениях (440/446 имеют `m_main`, 445 — `s_main`, 268 — DS2-вариант `s_ident_ds2`).
3. **Бинарный data-регион** (даёт ложные single-char срабатывания — фильтруется).
4. **`__inpa_startup__`** — разводка меню: лейблы пунктов, F-клавиши, вызовы джобов,
   payload'ы активаций.

### Типы экранов и что извлекается
- **`m_*` меню** → список лейблов пунктов (навигация). Пример m_main (RU):
  `Инфо, Идент, Кодировки, Ошибки, Поток данных, Активации, Адаптации, Выбор, ...`
- **`s_digital` / `s_status`** → строки **лейбл ↔ список результатов**, co-located:
  `"Input air condition, Air conditioning compressor"` затем `"STAT_AC_EIN;STAT_KO_EIN"`.
  Лейблы через запятую = колонки; результаты через `;` = позиционно им соответствуют.
  **Главный источник статусов** (co-located ~104 модуля).
- **`s_analog*`** → **только лейблы** (`"Rail-pressure, Charge-air pressure"`); привязка
  результатов косвенная (через `ergebnisUmrechnungAnalog*` + слоты переменных). Для live-
  значений — селекторы MW_SELECT (см. ниже), не co-located имена.
- **`s_ident` / `s_info` / `s_code`** → в `.ipo` пусто: контент формируется процедурой из
  результатов джоба. Рендерим сырой `JobResult` (part number, HW/SW, coding index …).

## Именование (дрейф по поколениям)
- `STATUS_*` = **имена джобов**.
- Результаты: у новых ЭБУ `STAT_*`, у старых (DME17, GS) — тоже `STATUS_*`. Парсер принимает
  оба (`_is_result_list`: голова `;`-списка матчит `^(STAT_|STATUS_|ID_|F_)…`).

## SGBD (.prg) внутри `.ipo`
- Появляется как (а) голый токен (`DDE40KW0`) перед вызовами джобов и (б) info-литерал IDENT
  `NAME,VARIANT` / `NAME/Vx.x,NAME2/…` (`DDE40KW0,D40M57A1`, `GS19/V1.06,GS19A/V3.01`).
- Экран может ссылаться на **несколько** SGBD (субсистемы: MSV70 → CAS/EWS3/EKP/…).
- Разбор: split по `[,/;\s]`, матч токенов против `ecu/*.prg`. Праймари — по близости к имени
  script'а (CFGDAT `ENTRY=<script>`), с L/R-разбором для двублочных DME (DM5212**L**0 vs …R0).
  Покрытие: маппинг script→SGBD закрыл 156→3 незамапленных записей каталога.

## Селекторы (DDE-батчинг)
И `STATUS_*`, и `MW_SELECT_LESEN_NORM` (сервис `2C 10`) идут через одну measurement-таблицу
`.prg`, поэтому имена результатов идентичны (`STAT_<mnem>_WERT`/`_EINH`). Селектор (2-байтный
PID) восстанавливается из таблицы `.prg` по мнемонике; до 10 упаковываются в один
`MW_SELECT_LESEN_NORM`. См. `docs/EDC15C-COMMS.md` и память `define-once-2c10-fps`.

## Фикстуры
- `SGDAT/S_FUNK_I.IPO` (674 Б) — минимальный полный модуль (unit-тест).
- `SGDAT/DDE40.IPO` — эталон (батчинг, s_digital + s_analog1..5).
- `SGDAT/DME17.IPO` — старое именование результатов (`STATUS_*`).
- `SGDAT/ABSASC5.IPO` — мульти-вариантные узлы (`_abs5/_asc5/_dsc3`).
- `SGDAT/MSV70.IPO` (609 КБ) — крупный, мульти-SGBD.
