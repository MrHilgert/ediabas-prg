# Технический долг: костыли и зоны неполной ответственности

> **Определение костыля (для этого документа):** узкий частный случай ради одной
> задачки — код, покрывающий только «x ради y» (только DDE40, только один концепт,
> только два имени job'а), вместо полного покрытия своей зоны ответственности.
> Не всякая паника или магическое число — костыль; они вынесены в отдельные разделы
> «Устойчивость» и «Мёртвый код».
>
> Составлено анализом кодовой базы (4 агента по слоям: VM, транспорт, API/prg/CLI,
> GUI) + оркестрацией согласованных решений (4 агента-архитектора по сквозным
> кластерам). Для каждого кластера: суть → позиции слоёв → **согласованное решение**
> → приоритет/риск.
>
> Намеренные, задокументированные воркэраунды (`got_response`+non-fatal xsend для
> многоадресного IDENT; `xawlen`→LEN@1 fallback + `awlen_set`; ImmStr через `blat`;
> спец-кодирование `enewset`) в костыли **не** включены — они покрывают контракт.

## Раздел А. Настоящие костыли (неполное покрытие ответственности)

### А1. Источник истины параметров протокола и формата кадра

**Суть.** Формат кадра и параметры протокола выводятся из узких частных признаков,
а не из полного разбора данных .prg.

**Позиции слоёв:**
- `config.rs:152,212` — `len_offset`/`len_add` из **концепта** (`0x0006→(3,5)`, иначе
  `(1,0)`), а не из фактического `CommAnswerLen`.
- `prg.rs:451` — `initial_comm_config` ищет **байтовую сигнатуру `28 80`** в байткоде
  → ложный разбор CommParameter (пара может встретиться в операнде).
- `config.rs:22` — `Protocol::from_concept` при неизвестном концепте **молча → Ds2**.
- `config.rs:243` vs `ds2.rs:65` — дефолт `interbyte_ms` рассинхронизирован (5 vs 0);
  VM стартует с `CommConfig::default()`, а транспорт уже построен из статического cfg.

**Согласованное решение (архитектор).**
Истина по **формату ответа** — рантайм `xawlen`/`apply_awlen` (уже верно, `awlen_set`
делает его авторитетным — **оставить**). Истина по **выбору транспорта + baud/parity
открытия порта** — статический разбор .prg. Обе фазы обязаны использовать **один
парсер и одни дефолты**:
1. Заменить сигнатурный поиск `28 80` на проход по **инструкционному декодеру**
   (проверенный desync-proof), вынести общий хелпер «первый CommParameter/CommAnswerLen
   из INITIALISIERUNG», звать его из статики.
2. **Сидировать VM** статическим `cfg` (`Vm::new_with_config`), а не `default()` — иначе
   до первого `xsetpar` VM и транспорт рассинхронизированы.
3. Неизвестный концепт: **не** делать `Error` (регресс для «неизвестный, но DS2»), но
   убрать молчаливость — `trace!`-warning + fallback DS2 (флаг `concept_known`).
4. `interbyte_ms`: `CommConfig::default()=0` (честный `ParInterbyteTime`), единственный
   литерал «5» — `DS2_MIN_INTERBYTE_MS` в транспорте; `Ds2Transport::new()=5` (чтобы путь
   `raw`, минующий `configure()`, тоже имел пол).
5. **Отклонить** «парсить CommAnswerLen статически» (config.rs:152) — заводит второй
   хрупкий сканер формата; формат ответа — прерогатива рантайм-`xawlen`.

**Приоритет:** высокий. **Шаги:** interbyte-дефолты → warning концепта → декодер-хелпер
→ сидирование VM. **Риск:** DDE40 (interbyte-пол держится только на `max()` — проверить
путь `raw`); IKI (новый хелпер должен выбрать *тот же первый* `xsetpar`). Прогон корпуса:
сравнить выбранный concept старым vs новым разбором.

### А2. Определение присутствия / liveness / идентификация варианта

**Суть.** «Присутствие ЭБУ» сведено к булеву «пришёл хоть какой-то байт», а выбор
ident-job — к угадыванию по 2-3 именам. Ни то, ни другое не покрывает контракт.

**Позиции слоёв:**
- `api/mod.rs:93` — presence = `vm.got_response()` (был **любой** ответ по шине); может
  зажечься от обмена к **другому** адресу при групповом опросе → ложный позитив.
- `result.rs:48` — `comm_ok |= other` **липкий**: раз true — навсегда; при обрыве связи
  в стриминге GUI не видит потерю линка.
- `api/mod.rs:132` — `identify_variant` хардкодит `["IDENTIFIKATION","IDENT"]` + поле
  `VARIANTE`; при ином имени — молча `Ok(None)` → берётся не тот SGBD.
- `worker.rs:220` — `probe_presence` хардкодит `["IDENT","IDENTIFIKATION","INFO"]`.
- `session:397` — `MISS_LIMIT=8` — магический порог дисконнекта.

**Согласованное решение (архитектор).**
Присутствие/liveness — не флаг, а **свойство линка к конкретному адресу во времени**.
Разделить один `got_response` на две сущности:
1. **job-scoped `responders: HashSet<u8>`** (reset каждый `run_job`): в `exchange_nonfatal`
   при непустом ответе вставлять **целевой адрес отправленного кадра**. → адресный и
   не липкий. Многоадресный IDENT работает: чужие/таймнутые адреса не попадают в множество.
2. **link-scoped `last_ok: Option<Instant>`** (переживает job'ы, не сбрасывается): liveness
   = `now - last_ok < within` (порог **временной**, производный от интервала опроса, а не
   магическая «8»).
3. `presence` (concrete-SGBD) = `responded_from(wake_addr)`; presence **группы** гейтить
   по факту результата `VARIANTE`, а не по comm.
4. Имя ident-job и имя поля-варианта брать из **метаданных .prg/GROUP** (`PrgFile::ident_job()`
   / `variant_result()`, дефолты `IDENTIFIKATION`/`VARIANTE`), не из литералов.
5. **Перенести `probe_presence` в lib** (`Session::probe_presence()`), убрать дублирующий
   список имён из GUI; GUI оставляет только оркестрацию групп и ре-open варианта.

**Приоритет:** высокий (сейчас даёт фейк-коннект/фейк-liveness). **Риск:** атрибуция по
адресу отправки (безопасно при request/response); для группы «основного адреса» нет —
не перепутать путь concrete vs group; обязателен дефолт имён при пустых метаданных.
**Связь:** memory `inpa-group-variant-selection` (tasks #23-25).

### А3. Конечный автомат коннекта в GUI

**Суть.** Логика коннекта размазана по 3 файлам с 3 разными критериями «можно
подключиться» — каждый покрывает свой узкий срез.

**Позиции слоёв:**
- `app.rs:253` — `start_connect` сразу ставит `Screen::Session`, но `Cmd::Connect` **не
  шлёт**; реальный Connect шлёт `lifecycle()` уже на экране сессии.
- События воркера дренируются в **двух** местах (`poll_connect` ecu_select + `drain_worker`
  session) в зависимости от активного экрана.
- **Три** предиката connectable: `script||prg` (app:265), `prg` (ecu.rs:87),
  `!sgbd||!groups` (session:457). Double-click карточки обходит enable-гейт кнопки.

**Согласованное решение (архитектор).**
Один явный КА `Link { Idle, Connecting, Connected, Failed }` в `App`, двигаемый (а)
действиями пользователя и (б) **единственным** обработчиком событий воркера в
`App::update` до `match screen`.
1. `begin_connect(code)` — **единственная** точка `Cmd::Connect` (сливает `start_connect`
   + `lifecycle`); `apply_event` — **единственный** дренаж (тело `drain_worker` +
   `poll_connect`). Поле-костыль `connect_attempted` удаляется (защита — само состояние
   `Connecting`).
2. **Один** предикат `connectable(&ScreenModule) = !sgbd.is_empty() || !group_files.is_empty()`
   — для кнопки, клика и гейта; `.ipo` грузить при выборе `ecu_sel` (экран 2).
   `Module::connectable()` (prg) разжаловать до справочной плашки.
3. Переход в `Session`: connectable-ЭБУ — **только по `Connected`** (до этого `Ecu` +
   модалка); structure-only (нет sgbd и групп) — сразу (транспорта нет по определению).
   Внутрисессионные гейт + `connecting_modal` **удаляются** — сессия тривиально корректна.
4. Обе модалки схлопнуть в один app-level `link_modal` (как `settings_modal`).
5. Асимметрия потери связи: первичный `Failed` — модалка на `Ecu`; потеря **уже
   установленной** связи (miss-limit) — баннер в `Session`, без катапульты на экран 2.

**Приоритет:** высокий (это корень путаницы с гейтом/модалкой). **Риск:** событие в кадр
перехода `Ecu→Session` должно обрабатываться до `match screen` (иначе теряется первый
poll — сейчас маскируется двойным дренажом).

### А4. Захардкоженные метаданные ЭБУ вместо данных из CFGDAT/.prg

**Суть.** Шина/адрес/скрипт/baud выводятся спецкейсом «дизель = DS2, 0x12, DDE40»
или ручной таблицей, вместо данных из CFGDAT/.ipo/.prg.

**Позиции слоёв:**
- `ecu.rs:155` — `engine_module` хардкодит DS2-кузова `E38|E39|E46|E53|E83`, марки
  `M47/M57`, адрес `0x12`, скрипт `DDE40`/`DDE40KW0.prg` — только под дизели.
- `ecu.rs:106` — ручная таблица `MODS` (~25 ЭБУ) как фолбэк для кузовов вне CFGDAT.
- `session:467` — `baud: 9600` в `Cmd::Connect` (должен из CommParameter .prg).
- `session:461` — фолбэк порта `"COM3"` (бессмыслен на Linux).
- `screens/mod.rs:175` — чип шины всегда печатает литерал `"D-CAN"` (по факту DS2).
- `api:44,52` — unknown concept → тихий DS2; CAN-baud `115200`, имя `INITIALISIERUNG`.

**Согласованное решение (архитектор).**
Три раздельных источника, слои не дублируют:
1. **CFGDAT/.ipo** (`catalog.rs`, генератор) — структура: какие ЭБУ, категории, лейблы,
   `script→.prg`. **.prg через `CommConfig`** — протокол/baud/parity/адрес. **Статика** —
   только конвенции.
2. Снести `engine_module`/`is_diesel`/`MODS`/`parse_years`; дизели уже в CFGDAT как
   обычные записи. `mods_for` = `entries_for(...).map(catalog_module)`.
3. `bus`/`addr` генерить **offline** (`gen_catalog.py` читает концепт+`wake_addr` каждого
   .prg → поля `CatEntry`), нет .prg → `"—"`, не выдумка.
4. `baud`: передавать `0` (`.prg` побеждает). Порт: убрать `COM3`, нет порта → «выберите
   порт», кроссплатформенный пикер. Шина в шапке: `Session::comm()` + поле в
   `Event::Connected` → рендер реального `Protocol` (до connect — `m.bus` из каталога).
5. Оставить захардкоженным допустимо: имена `INITIALISIERUNG`/`IDENTIFIKATION`
   (конвенции EDIABAS), control-baud `115200` (FTDI, не ЭБУ), таксономия категорий,
   дефолты debug-команд. «Тихий DS2» → `trace!`-warning.

**Приоритет:** средний (корректность витрины/шапки). **Порядок:** порт → baud → шина в
шапке → каталог-derived bus/addr + снос спецкейса → warning концепта. **Риск:** смысл
`addr` сменится (BMW-адрес узла → диаг-адрес EDIABAS `0xB8`); «bus» станет протоколом,
а не физической шиной — каталог и чип обязаны трактовать одинаково.

## Раздел Б. Устойчивость (паники и тихие подмены — не костыли, но баги)

**Корректность (неверный результат):**
- `vm:170` `arg_int` hex-first (см. А5) — **высокая**, молча неверные `parb/parw/parl`.
- `vm:1180` `a2y` = hex-разбор (см. А5) — **высокая**.
- `config.rs:22` unknown concept → DS2 (см. А1) — неверный транспорт/тихий таймаут.
- `api/result.rs:155` `get_i64/f64` → `unwrap_or(0)` для `Value::Data`: ошибка парса
  неотличима от настоящего нуля → возвращать `None`.
- `prg.rs:324` `num()` глушит плохой FACT_A/B в `0.0` → обнуляет канал молча.
- `vm:525,1711` деление на ноль → `0`/`0.0` (EDIABAS сгенерировал бы ошибку).

**Паники (индексация/underflow без проверки границ):**
- `prg.rs:412,426,429,432,53` — срезы/вычитания по **сырым указателям хедера** без
  bounds-check: на нестандартном .prg — паника. **Высокая** (главный источник риска).
- `prg.rs:36` `read_cstring_at` — `section[offset..]` без проверки.
- `vm:2137` `read_flt_src`, `vm:1704,1725,1128…` float/`par*` **off-by-one** guard
  (`ip+1` вместо `ip+2`) — паника на операнде у края кода. **Высокая**.
- `main.rs:373` `u16::from_le([hdr1,hdr2]) as usize - 3` — underflow при длине <3.
- `main.rs:287,531` `sort_by(...partial_cmp().unwrap())` — паника на NaN.
- `kwp2000.rs:76` `tel_length_bmwfast` индексирует `hdr[3..5]` без проверки длины.

**Единый принцип фикса:** все ридеры байткода/заголовков — через `code.get(...)`/
`checked_sub`, возврат `Option`/`Result`, деградация вместо паники (как уже сделано в
`ds2.rs::receive`). Общий рефактор, а не точечные заплатки.

**Магические числа (задокументировать/вынести в константы):** таймауты `2000/20/50`
(`config.rs:170`), `retry_nr78<100→3` (`config:225`), `MISS_LIMIT=8`, `*_tries<3`,
5-baud тайминги DS2 (`ds2:209`), `sleep(10/30)` KWP1281.

## Сводный приоритет

1. **А2** (фейк-presence/liveness) и **А1** (источник истины формата) — прямо влияют на
   корректность коннекта; сюда же паники `prg.rs` (Раздел Б).
2. **А3** (connect-FSM) — снимает архитектурную путаницу гейта/модалки, разблокирует
   надёжный UX.
3. **А4** (data-driven метаданные) — корректность витрины/шапки.
4. **А5** — по мере необходимости конкретных ЭБУ (напр. `xsendf`/KWP2000 для не-DS2).
5. Раздел В — попутная чистка (кроме `screens_gen.rs` — требует решения «подключить/снести»).
